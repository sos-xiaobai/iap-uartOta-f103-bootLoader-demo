# Bootloader 进入IAP模式 - 触发方式说明

## 概述

优化后的bootloader支持**4种方式**进入IAP升级模式，提供了灵活且可靠的升级触发机制。

---

## 🎯 四种触发方式

### 方式1: 未完成升级检测（自动）

**触发条件：** 上次升级过程中断（如断电、复位）

**优先级：** 最高

**工作原理：**
- 升级开始时设置升级标志
- 升级成功后清除标志
- 下次启动时检测到标志，自动进入IAP模式恢复升级

**串口输出：**
```
WARNING: Last update incomplete!
Enter IAP mode...
```

**用途：** 确保升级过程的可靠性，防止因意外中断导致设备变砖

---

### 方式2: APP无效检测（自动）

**触发条件：** 检测到APP固件无效或损坏

**优先级：** 高

**检测内容：**
1. 栈顶地址是否在有效RAM范围内
2. 复位向量是否在APP区域内
3. 复位向量是否为Thumb指令（最低位为1）

**串口输出：**
```
Application invalid!
Enter IAP mode...
```

**用途：** 首次烧录bootloader、APP损坏时自动进入升级模式

---

### 方式3: GPIO按键触发（可选）

**触发条件：** 启动时按住指定按键

**优先级：** 中

**使用方法：**

1. **在STM32CubeMX中配置GPIO：**
   - 选择一个GPIO引脚（如PA0）
   - 配置为输入模式（GPIO_Input）
   - 设置为上拉输入（Pull-up）
   - 设置用户标签（如"BOOT_KEY"）

2. **在main.c中启用代码：**

取消注释以下代码（第135-141行）：

```c
if (!enter_iap && HAL_GPIO_ReadPin(BOOT_KEY_GPIO_Port, BOOT_KEY_Pin) == GPIO_PIN_RESET)
{
    Bootloader_UART_SendString("Button pressed, enter IAP mode...\r\n");
    enter_iap = 1;
}
```

3. **修改引脚定义：**
   - 将 `BOOT_KEY_GPIO_Port` 改为实际的GPIO端口（如 `GPIOA`）
   - 将 `BOOT_KEY_Pin` 改为实际的引脚（如 `GPIO_PIN_0`）

**硬件连接：**
```
按键 ----+---- GPIO引脚
         |
        GND
```

**使用：** 按住按键，给设备上电，即可进入IAP模式

**串口输出：**
```
Button pressed, enter IAP mode...
```

**用途：** 手动强制进入升级模式，适合现场维护

---

### 方式4: 超时检测 - 串口命令触发（自动/手动）

**触发条件：** 启动后3秒内通过串口发送特定命令

**优先级：** 低（正常流程）

**工作原理：**
1. Bootloader启动后等待3秒
2. 在此期间检测串口是否收到以下任意数据：
   - 字符 `'U'` 或 `'u'`（手动触发）
   - IAP数据包头 `0xAA`（自动触发）
3. 收到命令后立即进入IAP模式
4. 3秒超时未收到，跳转到APP

**串口输出（等待过程）：**
```
Press 'U' to enter IAP mode, or wait to run APP...
Waiting ......
```

**串口输出（收到命令）：**
```
IAP command received!    // 收到 'U'
或
IAP packet detected!     // 收到 0xAA
```

**使用场景：**

#### A. 自动触发（推荐）
使用Python工具直接升级：
```bash
python iap_upload.py -p COM3 -f firmware.bin --version 1.2.3
```

工具会自动发送IAP数据包，bootloader检测到后进入升级模式。

**优点：** 全自动，无需手动操作

#### B. 手动触发
使用串口工具（如SecureCRT、Tera Term）：
1. 打开串口连接（115200波特率）
2. 给设备上电
3. 在3秒内按键盘 `U` 键
4. 进入IAP模式

**优点：** 简单直观，无需编程工具

**超时时间调整：**

在main.c中修改：
```c
uint32_t wait_time = 3000;  /* 改为其他值，单位：毫秒 */
```

**用途：** 正常升级流程，支持自动和手动触发

## 📋 完整的启动流程

```
设备上电
   ↓
硬件初始化
   ↓
串口输出欢迎信息
   ↓
【方式1】检查是否有未完成的升级？
   ├─ 是 → 进入IAP模式
   └─ 否 → 继续
   ↓
【方式2】检查APP是否有效？
   ├─ 无效 → 进入IAP模式
   └─ 有效 → 继续
   ↓
【方式3】检查是否按住按键？(可选)
   ├─ 是 → 进入IAP模式
   └─ 否 → 继续
   ↓
【方式4】等待3秒检测串口命令
   ├─ 收到 'U' 或 0xAA → 进入IAP模式
   └─ 超时 → 跳转到APP
   ↓
跳转到APP
   ├─ 成功 → 运行APP
   └─ 失败 → 进入IAP模式（异常保护）
```

## 🚀 使用建议

### 日常使用（推荐配置）

**保持默认配置：**
- ✅ 方式1: 未完成升级检测（已启用）
- ✅ 方式2: APP无效检测（已启用）
- ❌ 方式3: GPIO按键触发（注释掉，可选）
- ✅ 方式4: 超时检测（已启用，3秒）

**升级命令：**
```bash
python iap_upload.py -p COM3 -f firmware.bin --version 1.0.0
```

**效果：**
- 正常情况下，设备上电后3秒自动跳转到APP
- 使用Python工具时，自动检测并进入IAP模式
- 升级中断后，下次自动恢复

---

### 开发调试（建议配置）

**启用GPIO按键触发：**
1. 取消注释方式3的代码
2. 配置一个GPIO按键
3. 可选：缩短超时时间到1秒

**好处：**
- 方便手动进入IAP模式
- 不依赖Python工具
- 适合现场调试

---

### 生产环境（建议配置）

**加强保护：**
1. 保持所有自动检测方式
2. 可选：禁用方式4（不等待串口命令）
3. 添加版本检查机制

**修改方式：**
注释掉方式4的代码（第144-190行），直接跳转APP

**好处：**
- 启动更快（不等待3秒）
- 只能通过有效方式进入IAP
- 更加安全可靠

## 🛠️ 故障排查

### 问题1: 总是进入IAP模式，无法跳转APP

**可能原因：**
- APP固件未烧录或已损坏
- APP起始地址不正确

**解决方法：**
```bash
# 烧录新固件
python iap_upload.py -p COM3 -f firmware.bin --version 1.0.0
```

### 问题2: 无法进入IAP模式

**可能原因：**
- 串口连接问题
- 等待时间太短
- Python工具未正确启动

**解决方法：**
1. 打开串口工具，上电后3秒内按'U'键
2. 延长等待时间到5秒
3. 启用GPIO按键触发

### 问题3: 启动太慢

**可能原因：**
- 等待时间太长（默认3秒）

**解决方法：**
- 缩短等待时间到1秒
- 或者禁用超时检测（注释方式4）
